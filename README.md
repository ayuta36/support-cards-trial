# サポートカード

## 1. サポートカードについて

初めて会う人に、その人のことや関わるときの工夫を伝えるカードアプリです。事前に情報を記入し、相手や場面に合わせて必要な内容を共有できます。ブラウザで使い、アプリのインストールは要りません。

伝え方や好きなことなど本人らしさに関わる情報、活動上の工夫をカードに整理します。相手や場面に応じて共有するトピックを選び、必要な内容を探しやすくする設計です。

## 2. 解決したい課題

障がいのある方と初めて会う場面では、必要な情報は相手や役割によって異なります。たとえば学生には話しかけ方や意思表示、好きなことが、運営には活動を支える工夫や緊急時の連絡が必要になります。ほかにも、次のような課題があります。

- 知識や経験の違いから同じ言葉や説明が同じようには伝わらず、相手が何を知っているか確かめて前提から説明する必要がある。
- 情報が口頭、紙、メッセージなどに分かれていると、説明や引継ぎを繰り返したり、その場で必要な内容を探したりする負担が生じることがある。実際にどの程度起きるかは、利用場面で確かめる必要があります。
- 安全や医療の注意事項だけでは、意思表示や好きなこと、安心できる関わり方など、一人の人として関わる情報が伝わりにくい。
- 必要な内容を選ばず全て共有すると、受け取る側の負担や不要な個人情報の共有につながることがある。

共有した内容は受取人の端末に独立したコピーとして保存されます。自動更新や、こちらからコピーを削除する機能はありません。共有後の更新や削除の扱いも残る課題です。詳しくは「[5.3 共有する前に](#53-共有する前に)」を参照してください。

## 3. できること

- 人物ごとにプロフィールとトピックを記録し、チームごとに整理できます。トピックは指やマウスで並べ替えたり、ボタンで順番を変えたりできます（指操作は実機未確認です）。
- 学生向けの「はじめましてページ」と、運営向けの緊急時情報一覧を表示できます。
- トピックを学生向け、運営スタッフ向け、または家族向けに分けて、共有する範囲を選べます。
- 相手別に暗号化した共有ファイルを作成し、別の端末にコピーとして読み込めます。端末の共有メニューが使える場合はLINEなどを選べます。使えない場合はファイルを保存して渡します。
- 人物ページを印刷したり、内容を端末の日本語音声で読み上げたりできます。
- 人物ごとに、この端末だけのメモを残せます。メモは共有、書き出し、印刷、バックアップに含まれません。

## 4. 使い始める

公開中の試行版は[こちらから開けます](https://ayuta36.github.io/support-cards-trial/)。初回は架空の人物が入ったサンプルが表示されます。実在の人の情報を入れる前に、サンプルで作成、共有、読み込みを一通り試してください。現場での使いやすさや効果、iPhone・Android 実機での共有操作はまだ確認していません。

1. 最初に端末のパスコードを設定します。忘れると端末内のデータを復元できないため、安全な場所に控えてください。
2. サンプルのチームでカードを開き、トピックを見ます。新しいチームとカードを作り、必要な情報を入力します。
3. 共有するときは相手を選び、確認画面で含まれる内容を見ます。共有ファイルと共有パスコードは別の方法で相手に渡します。受け取る側はファイルを読み込み、共有パスコードを入力します。

## 5. 保存と共有

### 5.1 パスコード

アプリでは、役割の違う2種類のパスコードを使います。

| 項目 | 端末のパスコード | 共有パスコード |
|---|---|---|
| 使う場面 | アプリを開くとき | 共有ファイルを読み込むとき |
| 守る範囲 | そのブラウザに保存した全チームとカード | その共有ファイル |
| 決めるとき | 初回設定時 | ファイルを書き出すたび |
| 長さの目安 | 8文字以上 | 12文字以上、または単語を4つ以上 |
| 保管 | 忘れると端末内のデータを復元できません | ファイルとは別の方法で受取人へ伝えます |

どちらも4文字以上で設定できます。長く、推測されにくいものを使ってください。共有パスコードの入力欄は伏せ字になりません。周囲から画面を見られない場所で入力してください。パスコードそのものは保存されず、忘れた場合は開発者を含め誰も復元できません。短く推測されやすいパスコードでは、暗号化していても内容を知られるおそれがあります。

### 5.2 保存と控え

カード、写真、トピック、メモなどの内容は端末ごとにブラウザ内へ暗号化して保存され、自動同期はありません。文字サイズやテーマなどの設定、保存日時など一部の補助情報は暗号化されません。端末の故障、ブラウザの保存データ消去や自動整理で内容が失われることがあります。控えは「すべて」を選んで、暗号化した Markdown ファイル（`.md`）として書き出し、ファイルと共有パスコードを別々に保管します。

この `.md` はテキストエディターで読むための文書ではなく、アプリで共有パスコードを入力して読み込むファイルです。`.md`という拡張子自体が安全性を持つわけではありません。ファイルを開けばアプリ名が分かり、ファイル名から書き出し日時、ファイルサイズから写真の多さが分かることがあります。旧版の暗号化 `.scard` は通常の読み込みでは開けないため、設定にある変換機能で `.md` に包み直します。変換では暗号化を解かず、共有パスコードも変わりません。

共有メニューから渡す場合は、暗号化したファイルと定型文が選んだアプリに渡ります。アプリは送信先や送信完了、相手の受け取りを確認できません。パスコードは別の方法で伝えてください。

読み込みは上書きや同期ではなく、新しいチームの追加です。控えとして受け取った内容は閲覧専用で、「すべて」の控えに限り、内容を確認した後にこの端末で編集できるようにできます。重複したチームを削除する前に、残す内容を確かめてください。

受け取った内容の閲覧専用は、誤操作を減らすための制限です。データが端末にある限り技術的に回避できるため、アクセス制御や権限管理の代わりにはなりません。

### 5.3 共有する前に

相手別の共有で選ぶのはトピックの範囲です。チーム全員の名前、写真、ひとこと紹介、最終更新日は、どの相手にも含まれます。共有前の確認画面にはトピック本文が出ないため、元のカードを開いて内容も確かめてください。

| 書き出す相手 | 入るトピック |
|---|---|
| 学生（一緒に参加する人）向け | 「学生」に見せると決めたトピック |
| 運営スタッフ向け | 「運営」に見せると決めたトピック |
| すべて（家族どうし・控え用） | チームの全データ。家族のみのトピックや、一覧にない保存データも含みます |

どの相手を選んでも、チーム全員分の情報が入ります。書き出し画面で人物やトピックを個別に選ぶ機能はありません。各トピックの共有設定は、事前に確認してください。この端末だけのメモと、受取元を示す端末内の情報は共有しません。ひとこと紹介はどの相手にも含まれるため、医療情報などを書くとそのまま共有されます。

共有した内容は受取人の端末に独立したコピーとして保存されます。こちらから相手のコピーを更新したり削除したりはできません。不要になったコピーは受取人側で削除し、紙で渡した場合は回収してください。渡したファイルや印刷物も、相手の手元に残っていないか確認が必要です。

### 5.4 この端末だけのメモ

メモはカードやチームと同じく、この端末の暗号化された保存に入ります。共有、バックアップ、印刷には含まれず、同じ端末を解錠できる人には見えます。ロック時に未保存の下書きは破棄されます。カードやチームを削除すると保存済みメモも消えます。本人や家族が見ても困らない範囲で、当日の運用に必要な内容だけを記録してください。医療的な指示や判断、診断名、パスコードは書かないでください。

## 6. 利用上の注意

アプリは、カードやメモの内容をサーバーへ送信せず、広告やアクセス解析も行いません。ページを開くときは、公開先のGitHub Pagesからアプリのファイルを読み込みます。GitHub Pagesの利用には公開先サービスの規約が適用されます。

暗号化は端末やブラウザの安全性を保証しません。

GitHub Pagesでは、同じアカウント内の別ページがブラウザの保存領域を共有する場合があります。そのページのコードがこのアプリの保存データを書き換えたり消したりする可能性があるため、実在する人の情報を使う前に、公開先を管理する人と利用環境を確認してください。

共有や印刷・PDF、読み上げを使うと、内容が端末の外へ出たり、周囲に聞こえたりします。共有ファイルは暗号化されますが、印刷物やPDFは暗号化されません。共有先のアプリ、メール、クラウドなどに残ったファイルの保存・転送・削除は、それぞれのサービスと利用者の管理です。共有先や受取人への送信完了をアプリは確認できません。読み上げの声も周りに聞こえることがあります。

15分操作がないと自動でロックし、他のアプリに切り替えたときも画面をロックしてぼかします。解錠中は画面を見られる可能性があるため、使わないときはロックし、端末自体にも画面ロックを設定してください。

実在する人の情報を記録・共有する前に、本人が伝えられる方法で、記録内容と共有先について本人の意思を確かめてください。必要に応じて、本人が信頼する家族や支援者とも相談してください。アプリは入力内容や連絡先、対応方法の正しさを確認しません。医療行為や医療判断の代わりにはならず、緊急時は医療機関・救急（119）の指示に従ってください。

不具合は[GitHub Issues](https://github.com/ayuta36/support-cards-trial/issues)へ報告できます。実在する人の情報、共有ファイル、パスコードは載せないでください。

## 7. 開発について

ビルドや外部ライブラリの導入は不要です。開発には Node.js を使います。自動テストは次のコマンドで実行できます。

```sh
node test.mjs
```
